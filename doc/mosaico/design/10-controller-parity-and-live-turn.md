# 手机与 Mosaico 功能对齐及实时转身实现

> 2026-10-30｜ESP 0.4.1 / 游戏接收端 1.4.1。
> 本文记录本轮代码实现；测试与实机状态见末尾，不能将浏览器模拟写成 iPhone 真机通过。
> GATT 仍仅是 [独立后续方案](09-ble-gatt-direct-controller.md)，本轮未实现蓝牙。

## 1. 手机原来缺少顶排转身吗

核对本轮修改前的代码，手机和 ESP 0.4.0 已经都有顶排转身：
手机 `web/controller/gestures.js` → `ControllerLink.turnBy()` → JSON → 游戏输入路由。
旧规则是一格门槛，门槛后每格 90°。手机不是缺少该功能，本轮是统一修改门槛、幅度和反向行为。
实际手机若无效果，需要同时核对页面资源、游戏接收端版本和当前运行服务，不能仅凭源码判断部署已更新。

## 2. 功能对照与平台差异

| 能力 | 手机网页 | Mosaico |
|---|---|---|
| 左开火、右瞄准 | 双触控主键 | 双实体主键及对应按键灯 |
| 中心圆短点跳跃、中心拖动移动 | 已有，保留 | 已有，保留 |
| 外围八个功能短点 | 已有，保留 | 已有，保留 |
| 顶排横滑转身 | 本轮新规则 | 本轮相同规则 |
| 拖动后不误发功能、按起点锁定、首指所有权 | 保留 | 保留 |
| 完整体感姿态与手动转身叠加 | 已实现；需要可信 HTTPS、传感器授权与实际数据 | BMI270，应用内校准 |
| 校准 | 点击启用体感/重新校准，建立握姿参考 | A+B 按住约 800ms，再全部松开记录握姿 |
| 连接状态 | 跳跃圆环绿/红、四灯 | 同一状态语义，实体灯 |
| 受击等反馈 | 灯光闪烁；支持 Vibration API 才能驱动手机震动 | 马达及实体灯 |
| 断线释放、有效会话持续重连 | 页面运行且浏览器允许时重试 | 应用运行时重试 |

iPhone Safari 的网页震动限制不能靠补齐手柄代码消除；局域网 HTTP 下体感被安全上下文检查阻止。
手机已有体感灵敏度、仅瞄准启用和触控观察备用选项；ESP 沿用当前固定配置。
控制功能与方向语义对齐，不要求把系统权限、传感器或实体输出能力伪装成完全相同。

## 3. 本轮确认的实时滑动规则

- 仅从顶排三个功能格起手的拖动可以转身；中心起手始终移动。
- 起手后水平位移严格超过半格，激活本次转身；恰好半格不转。
- 激活门槛之后，每横向滑一格转 180°；滑 1/3 格转 60°，按实际位移实时更新。
- 一次按住只激活一次；之后左右回滑立即反向，不重新进入半格死区。
- 停手不继续转，松手保留最终朝向；不限制一次按住只能转 180°。
- 顶排短点仍执行原功能；拖动后不补发换弹、切武器或手雷。
- 纵向偏离起点超过半格仍取消本次转身，已产生的转角保留。

“一格”是相邻功能格的列间距，不是整个九宫格的宽度。
手机在按下时读取实际列间距 W；ESP W=152 个正常握持逻辑像素，激活距离为 76 像素。
两端使用同一归一化比例，不要求手机 CSS 像素与 ESP 逻辑像素相同。

## 4. 角度与反向计算

设 d 为当前触点相对按下起点的水平位移，右正；W 为一格距离。
激活前，在 |d|≤W/2 时转角为 0。
第一次越过门槛时，锁定锚点 a=sign(d)×W/2；锚点不随之后的反向滑动改变。
激活后，本次手势角度为 θ=(d−a)×180/W，每次只应用 θ 相对上次的差值。

同一次向右激活后的示例：

| 从最初按下起的位移 d | 本次手势累计转角 |
|---|---|
| W/2，尚未越过 | 0° |
| W/2 + W/3 | +60° |
| W/2 + W | +180° |
| 回滑到 W/2 | 0°，立即回转，不是重新等待激活 |
| 再回滑到 W/6 | −60° |
| 再向右到 3W/2 | +180° |

首次采样可能已越过门槛，超过部分照常计算，避免快速滑动被忽略。
两端门槛轨迹均缩为半格；激活后保持金色提示，箭头随实际转动方向改变。

## 5. 大幅快速转身与协议兼容

旧 `turn` 仅保留 [-180,180] 的圆周角。若一次更新跨过 180° 或多包被合并，
游戏只看最短圆周差值，可能把 +270° 当成 −90°，恰好 180° 也存在方向歧义。
新灵敏度更容易触发该问题，因此两端新增可选 `turnTotal` 完整累计角度快照。

- 手机使用 Number、ESP 使用 double 保存未取模总角度；普通松手、释放和有效会话重连均保留。
- JSON 同时发送旧 `turn` 和新 `turnTotal`；后端校验有限数值及 ±1,000,000,000° 边界。
- 输入合并取最新 `turnTotal`，不能逐帧求和；中间快照丢失仍保留完整净转角。
- 游戏 1.4.1 优先用总角度差值，正确处理 +180°、+270°、完整圈数和快速反向。
- 旧客户端不发 `turnTotal` 时保留旧圆周算法；不能承诺旧游戏接收器具备新快滑能力。
- 重连/暂停恢复的首个中立帧只建立累计角度基线，不重放期间的转身。
- 新绑定建立独立基线；`turnTotal` 不属于保持输入，不影响中立判定。

体感仍通过 `pose.id/q` 的完整相对姿态传输；手动转身改变持久观察基准，体感回正不撤销它。
本轮继续使用 WebSocket + JSON，没有新增蓝牙或改变 User/Share/Device 鉴权体系。

## 6. 不重复转动与发送节奏

不采用“超过 10° 才更新画面”的硬量化；它会造成慢滑跳变，也可能漏掉松手前不足 10° 的尾角。
手势实时计算完整角度；零增量不标记新的转身更新，两端均忽略零增量。
游戏只应用与上次已应用快照的差值，相同角度不重复转动。
取余数仅用于兼容 turn 字段；判方向、去重和差值优先用未取模 turnTotal。

连续输入合并到约 60Hz 发送节奏，按键和松手及时同步；最终角度保留在快照中，不因抬手归零。
完整 input 同时携带移动、按键和姿态，因此 turn 不变时仍可能因体感或保持输入而发送。
不能只根据转身角度不变停止整个输入流，否则会使 150ms watchdog 误判掉线并停控。
未来若单独优化转身字段频率，可评估“距离上次发送角度 1～2° + 时间上限 + 松手补齐”；
本轮不新增该量化门槛，也不承诺仅修改 turn 能减少全部体感消息。

## 7. 实现位置

| 层 | 文件与职责 |
|---|---|
| 手机手势 | `web/controller/gestures.js`：半格门槛、锁定锚点、实时位移与反向 |
| 手机轨迹/说明 | `turn-guide.js` / `index.html`：半格提示与操作说明 |
| 手机发送 | `web/controller/link.js`：完整累计角度及生命周期保留 |
| ESP 手势 | `device/esp32/main/gesture.c/.h`：与 JS 相同的状态机与比例 |
| ESP 轨迹 | `controller_trace.c/.h` / `controller_ui.c`：半格反馈、锁定门槛和反向箭头 |
| ESP 状态/发送 | `controller.c/.h` / `controller_link.c` / `controller_debug.c`：double 总角度、JSON 与诊断 |
| 宿主协议 | `server/app/devices/protocol.py`：新字段校验；队列原有最新快照合并规则继续适用 |
| 游戏插件 | `game/input-router.js`：完整转角差值、旧客户端兼容及恢复基线 |

游戏插件位于独立仓库，版本由 1.4.0 更新到 1.4.1；ESP 应用版本由 0.4.0 更新到 0.4.1。
