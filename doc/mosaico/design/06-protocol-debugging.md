# 无实机协议调试与验证方案

> 草案｜2026-10-28｜只记录接口与验证方法，不开发调试页或模拟器代码。
> 以[实时协议](03-pairing-and-protocol.md)为准；同一WSS+JSON供工具、模拟器、手机与ESP使用。

## 1. 不等机器的开发顺序

服务端提供生成码、join、reconnect和JSON路由 → 游戏InputRouter接入 →
通用WebSocket客户端验证 → 浏览器模拟手柄连续操作 → 手机交互适配 → ESP硬件适配。

无实机阶段即可验证：扫码凭证对应当前玩家、移动/视角/开火/功能动作、反馈、重连、权限与断线。
不能替代：摄像头识读、真实陀螺仪轴向与漂移、手机权限、多点触控、马达/灯和续航。

## 2. 使用通用WebSocket调试工具

选用能直接建立WebSocket并收发文本帧的工具即可，无需ESP SDK、专用客户端或必填hello。

1. 用User或Share身份在游戏中生成本人设备码，取得其连接URL。
2. 将HTTPS scheme改为wss，其他路径、bindKey与token保持原样；本地HTTP开发可对应ws。
3. 连接成功后应立即收到bound，保存当前resumeToken用于本次会话重连测试。
4. 发送完整中立input，再按下方JSON逐项验证；seq从1递增，不重复使用。
5. 单次功能与视角可手发；持续移动/开火需要工具定时发送，或使用后续浏览器模拟手柄。
6. 关闭连接验证150ms停止，再用reconnect地址接续；不重复使用已消费的join URL。

普通GET打开页面不会占用配对码；第一次有效WS连接才占用。
工具与真实设备一样受鉴权、限流和watchdog约束，不增加绕过权限或关闭watchdog的调试入口。

## 3. 可复制的最小消息

初始化/全部松开：

```json
{"type":"input","seq":1,"move":{"x":0,"y":0},"look":{"yaw":0,"pitch":0},"buttons":{"fire":false,"aim":false}}
```

向前走，每20ms左右发送同样状态并递增seq：

```json
{"type":"input","seq":2,"move":{"x":0,"y":1},"look":{"yaw":0,"pitch":0},"buttons":{"fire":false,"aim":false}}
```

停止移动，同时向右看5度、向上看2度（这帧只发送一次）：

```json
{"type":"input","seq":3,"move":{"x":0,"y":0},"look":{"yaw":5,"pitch":2},"buttons":{"fire":false,"aim":false}}
```

按住瞄准与开火；定时重复状态，但look保持0，避免重复转镜头：

```json
{"type":"input","seq":4,"move":{"x":0,"y":0},"look":{"yaw":0,"pitch":0},"buttons":{"fire":true,"aim":true}}
```

全部松开，然后跳一次、换弹一次：

```json
{"type":"input","seq":5,"move":{"x":0,"y":0},"look":{"yaw":0,"pitch":0},"buttons":{"fire":false,"aim":false}}
```

```json
{"type":"action","seq":6,"action":"jump"}
```

```json
{"type":"action","seq":7,"action":"reload"}
```

上述为独立步骤示例；实际定时重复会消耗更多seq，下一条继续从实际最新值递增。
一次input只保持到后续状态或150ms超时：手动点一次不能让角色一直走，属于正确行为。
action是一次触发，不按60Hz循环发送；游戏可能因冷却/死亡/当前阶段拒绝，ack应反映真实结果。

心跳可单独手发：

```json
{"type":"ping","id":1,"t":12345}
```

## 4. 浏览器模拟手柄（后续开发交付）

在Anka本地开发工具中提供小型模拟页，不作为生产常驻App，不接入另外一套传输协议。
页面接收join URL并像真实设备一样绑定，无法跳过扫码凭证或占用第二台席位。

| 控件 | 发送行为 | 可观察效果 |
|---|---|---|
| 方向盘/WASD | move模拟量，60Hz | 本人角色移动，松开停 |
| 开火/瞄准按钮 | buttons按住/释放 | 连发、ADS、组合操作 |
| 视角水平/垂直控件 | 每次操作生成look增量 | 旋转方向、角度、相机限位 |
| 九功能按钮 | 单次action | 跳跃与八外围功能 |
| 停止发送/断开 | 停input或关闭WS | watchdog释放与网络重连 |
| 当前真实状态 | 接收state/feedback/ack | 生命、弹药、冷却、动作拒绝原因 |
| JSON收发日志 | 展示时间、seq、消息 | 检查收到/转发/执行，token脱敏 |

模拟页自动维护seq、连续发送和中立帧；主键短按也保留边沿，不靠人工快速连点调试工具。
如支持消息录制/回放，只记录非秘密操作，不录join/reconnect token。
回放用当前会话重新编号和重新定时，不重放旧凭证、连接标识或真实游戏结算。

## 5. 无实机验收清单

| 测试 | 操作 | 期望 |
|---|---|---|
| 绑定对应本人 | 分别由User与Share生成码连接 | 只控制各自角色；玩家人数不变 |
| 一人一台 | 两客户端同时连接同码 | 只有一个绑定成功，不接管已有设备 |
| 普通预览 | 先GET再WS连接 | GET不占用；WS完成绑定 |
| 过期/重放 | 超时连接或重复使用旧码 | pair_expired/pair_used，无输入权限 |
| 用户态隔离 | 只有User Cookie但无设备token | Device join拒绝 |
| 移动与停止 | 定时向前输入后发中立 | 方向正确、松开停、斜向不超速 |
| 视角合并 | 多帧look右转增量 | 合计角度正确，不丢、不重复 |
| 开火边沿 | 很短的fire true→false | 至少一次正常开火机会，之后不连发 |
| 单次功能 | 一个action发一次/重复seq | 一次动作，重复不执行 |
| 真实反馈 | 开火、换弹、受到伤害 | state来自游戏，ack不是伪成功 |
| 输入停更 | 只保留ping，不发input | 仍在150ms左右停止移动/开火 |
| 断网重连 | 持resumeToken重连 | 同一目标、新连接、先中立、不补旧动作 |
| 撤权 | User退出、Share被踢、游戏关闭 | 立即停输入，旧resumeToken失效 |
| 异常消息 | 缺字段、越界、重复seq、洪泛 | 明确错误，不破坏其他玩家连接 |

先验证协议链路和可玩性，再调真实硬件传感器与触控手感；所有频率和超时仍是初始设计值。
