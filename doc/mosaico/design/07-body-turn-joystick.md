# 身体转向与浮动屏幕摇杆方案

> 2026-10-29｜历史未采用建议。用户改用中心起手移动、顶排横滑一格转身，见08-center-move-top-row-turn.md。
> 当前手机继续使用局域网HTTP，可信HTTPS配置沿用既有说明。

## 需求理解

用户已确认此前需求实现。本次希望屏幕除前后/左右移动外，还能像操纵杆一样让身体转弯、旋转；陀螺仪继续控制看的方向。

区分三个状态：移动向量、身体朝向、观察/瞄准朝向。身体转身需要持久的方向基准，陀螺仪相对观察叠加在该基准上。转身后把手柄回正，不应把身体拉回原方向。

## 当前代码事实

- ESP gesture.c 和手机 GesturePad 已输出连续二维向量，可以斜向或圆周滑动，未限制为四方向。
- 游戏 engine.js/updatePlayer 通过lookYaw将移动向量转换到世界坐标。
- 同一函数每帧将人物整体朝向相机瞄准射线，身体/观察尚未独立。
- ControllerPose每帧由完整相对姿态计算镜头。新增屏幕转身时，须改变镜头的持久基准，再叠加体感，避免下一姿态包覆盖屏幕转身。
- 联机部分也以lookYaw发送yaw。引入独立身体朝向，需要同步身体与瞄准方向的含义，保持伤害权威和枪口/动画一致。

## 三种选择

| 方案 | 体验 | 取舍 |
|---|---|---|
| 身体随移动方向转身 | 推向哪里，就朝哪里走 | 简单自然，但左右输入不再保持原来的横移，原地转向还需补充 |
| 常驻转向摇杆 | 上下前后，左右原地旋转，斜推走弧线 | 单指就能驾驶式转弯，横移需切模式 |
| 普通滑动移动＋长按进入转向摇杆 | 原操作保留，新增长按转向，松手退出 | 推荐；支持横移、原地转身与转弯，转向前增加短暂确认时间 |

推荐第三种。单指即可使用，保留九宫格九个点击功能、双实体键和目前的移动手感，不要求持续双指或借用开火/瞄准键。

## 推荐的操作规则

| 操作 | 结果 |
|---|---|
| 短点某个功能格后抬手 | 执行该格功能，与现有一致 |
| 按下后马上滑动 | 进入普通移动，保留前后、横移、斜向 |
| 原地按住约250ms且未超过移动阈值 | 进入转向摇杆，以变色圆环和短震动确认 |
| 转向模式向左/右推并保持 | 身体持续向左/右旋转；推得越远转得越快 |
| 转向模式向前/后推 | 沿身体前后方向移动 |
| 转向模式向左前/右前推 | 向前走，同时转弯，形成弧线 |
| 转向模式向左后/右后推 | 后退并按指示方向转身，水平符号不因倒退翻转 |
| 转向模式回到中心 | 停止移动和旋转，仍保持该模式直到抬手 |
| 抬手/取消/断线/后台 | 移动和转向归零，保留已经转到的身体朝向 |

一次触摸只决定一种模式。进入普通移动后不会因为停住手指又变为旋转；进入旋转后抬手不触发功能格。长按确认后即消费此次点击，即使没有转动也不补发跳跃/换弹。功能点击在抬手判定。

普通移动采用身体前方作为前进参考。陀螺仪向旁边看时，正在前进的角色仍沿身体方向行走。键鼠与原有游戏本机触控保持原操控配置，设备输入显式选择这套规则。

## 视觉与反馈

待机保留九宫格。按下时出现轻量圆环；普通拖动为青色摇杆，转向模式变为金色并显示旋转弧/箭头。中心点为本次触摸的原点，手指偏移为摇杆帽位置。

转向状态可淡化原功能图标，保留轮廓，防止误以为抬手会执行某项功能。抬手后短暂淡出并恢复功能格。保留中心跳跃按钮绿色/红色的连接语义，摇杆的模式提示不复用连接颜色。

接近屏幕边缘时，对浮动原点作有界调整，使左右满量程都可达到；不触发页面切换或退出。手机与ESP交互一致，绘制精度与物理尺寸分别适配。

## 镜头、身体与射击

- 身体朝向是游戏内持久状态，由屏幕转向控制。
- 镜头水平角由身体/转向基准叠加当前相对体感观察角；镜头俯仰继续由当前体感控制。
- 屏幕转身会带动观察基准，使玩家能用手指完成大幅转身；手柄只需承担精细观察，无需实物转满一圈。
- 陀螺仪回正恢复相对观察偏移，保留屏幕已经转到的方向。断线释放输入也不能抹掉身体方向。
- 第一人称主要通过画面和行进方向体现身体转身；第三人称可直接看到身体转动。
- 角色下半身与上半身瞄准应协调：下半身表现身体方向，头/躯干/武器在合理范围内跟随观察方向。大角度回看时要定义身体跟随与瞄准限位，避免扭转和向后穿身射击；具体容许角度为后续动画实测参数，不擅自改变命中规则。
- 子弹仍沿现有准星/瞄准射线计算，保持现有伤害权威。联机分别表达身体朝向与瞄准方向，避免其他玩家看到相反朝向或错误枪口。

## 起步参数（提议值，尚未实测）

| 参数 | 起步建议 |
|---|---|
| 长按确认 | 约250ms，允许在220–300ms之间调手感 |
| 触摸模式判定 | 复用现有移动阈值，并按物理屏幕缩放 |
| 转向死区 | 摇杆半径的约12% |
| 最大旋转速度 | 约120°/秒，可调90–180°/秒 |
| 转向曲线 | 中心细、外圈快的非线性曲线 |
| 转向平滑 | 约50–80ms起步；抬手立即归零，不做持续旋转惯性 |
| 转向范围 | 可连续转360°，身体方向按角度环保存 |

转向输入应表达强度/角速度，而非把摇杆位置映射成某个固定朝向：一直向左推就一直左转，回中/抬手就停。游戏按时间步长积分身体方向，不按网络包数量累计。

这与陀螺仪的完整相对姿态并不冲突：体感包表示当前观察姿态，转向轴表示当前持续转向指令。

## 接入范围

1. ESP和手机：增加Pending/Move/Steer状态判定，浮动摇杆、变色弧线和确认反馈。
2. JSON输入：保留move、pose、buttons，增加可选turn轴，范围[-1,1]；旧客户端缺省为0。不增加配对步骤或鉴权体系。
3. 宿主：校验turn，连续队列保留最新值，neutral判断包含turn，超时/断开释放转向，不重放断线指令。
4. 游戏：身体基准、体感合成、身体相对移动、模型转身和上半身瞄准协调。
5. 联机：身体朝向与观察/射击方向分别同步和解释，沿用原伤害权威。

## 开发与验收建议

先在浏览器模拟输入中完成移动/转向/体感的组合，再接手机手势，最后更新ESP。首轮交付一种明确的长按转向操作，之后根据实测决定是否提供常驻转向设置。

必须验收：

- 点按功能、快速拖动、轻微抖动和长按四种操作不互相误触。
- 持续左/右推可原地连续旋转，松手立即停止且保持新方向。
- 前推不转、横推只转、斜推走弧线，后退转向符号直观一致。
- 转身90°后手柄回正不会恢复原身体方向。
- 保持前进时转动陀螺仪，只观察，不无意改变行走方向。
- 转向、观察、开火/瞄准同时使用时不抢输入；上半身和枪口方向一致。
- 丢帧/断线/页面后台不会持续转圈；重连需要neutral，恢复后无旧输入回放。
- 第一/第三人称、单机/真实Share联机的移动、方向、瞄准和远端动画一致。
