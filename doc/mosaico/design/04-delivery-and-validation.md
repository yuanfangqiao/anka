# 开发方案、工程拆分与验收

> 设计记录｜2026-10-28｜以下保留方案期的职责划分；用户随后批准实施，实际结构与验收见 [实施记录](../IMPLEMENTATION.md)。
> 本期控制复杂度：一人一台手柄，一个固定九宫格配置；手机或 ESP 二选一。

## 2. 固件技术路线

以官方 Vibe 仓库锁定的 ESP-IDF master 提交 `7b9cc1ac79f865983f59bb8ff3ff43eb74ff1dbe`
和 `esp32s31` 为基线；BSP、utils 锁定提交见 [资料索引](../SOURCES.md)。
不使用通用 ESP32-S3 工程，也不直接用 BSP 最新分支替换已验证的消费版本。
后续在 `device/esp32/` 建消费工程和自己的依赖锁；`doc/mosaico/upstream/` 仅作本地研究资料。

UI 优先使用 BSP 已有显示/触控与 LVGL 能力，保持手柄专用的低开销界面。
无需初始化 Raylib 或加载 3D 游戏引擎；手柄只显示操作和状态，不运行游戏世界。
保留官方 Vibe Mode / Recovery 路线，独立应用入口使用受支持的分区/资源打包方式。
第一次刷写前先核实板版本、分区和备份；不把恢复出厂全镜像当作日常更新包。
设备操作沿用官方 mosaico CLI，开发阶段先 doctor / 构建检查，再明确指定唯一设备。

| 环节 | 初始目标 | 工程措施 |
|---|---|---|
| IMU | 200Hz 采样，实际效果实测 | BSP 默认为 100Hz，显式配置后测 I²C 负载/丢采样 |
| 双键/触控 | 高频读取、快速去抖 | GPIO/触摸模式按扩展模块能力；边沿识别由应用完成 |
| 网络 | 60Hz 状态 + 即时动作/释放 | 独立发送任务，最新状态覆盖，不阻塞触控采样 |
| UI | 30–60fps 目标 | 局部重绘、避免每帧重新分配大块内存 |
| 反馈 | 小型、有界、可取消 | LED 批量更新，马达限幅，不在传感器读取中阻塞 |
| 电源 | 活跃/空闲不同策略 | 调暗屏幕与灯；活跃输入不深度休眠；低电提示 |

使用官方 `esp_websocket_client` 建立 WSS，配置 CA 信任链和主机名验证，禁用跳过证书验证。
可靠时间同步后验证证书有效期；时间/证书失败有可理解提示，不退回明文传控制凭证。
网络重连指数退避；触控/按键/IMU任务不能等待 TLS 握手或 JSON 输出。
NVS保存校准、Wi-Fi引用和配置版本，resumeToken仅留应用内存。
日志对URL配对/重连token脱敏；重启应用重扫，不开发长效设备注册。
模块拔出先释放两键并停控，屏幕提示插回；不要沿用最后一次按下值继续射击。

## 3. Anka 与游戏接入

新增 devices 插件启用项、路由薄挂载、静态手柄入口、Vite HTTP/WS 代理与部署路径。
`/controller` 和设备 API 不使用账号壳回退，也不缓存配对响应、凭证或实时状态。
PWA 缓存仅保存版本化静态手柄资源；升级不能在对战中强制刷新控制页。
用/v1固定协议大版本；升级使用明确新路径，不做首帧协商；旧SW不能静默错配。

游戏端先提取统一 InputRouter：本地键鼠、游戏触控、Device 输入都调用动作入口。
保留现有发动动作/联机权威；Device 不直接改角色坐标、生命、弹药或战斗结算。
第一/第三人称视角使用统一 yaw/pitch 更新；相机平滑不重复累计网络角度。
接入弹层与设备状态遵循宿主导航/返回生命周期；关闭页面与插件teardown结束绑定并释放输入。
本期不新增一个常驻「设备管理」App，只在游戏里显示当前设备和解除按钮。

## 4. 分阶段开发

每阶段都交可验证结果；阶段通过才进入依赖它的下一阶段，不把手机可用等同 ESP 已完成。

| 阶段 | 交付物 | 退出标准 |
|---|---|---|
| P0 设计评审 | 本方案、动作表、协议、鉴权表、硬件差异 | 明确本期一人一台与固定布局，未开始功能开发 |
| P1 硬件与输入验证 | ESP 最小输入自检、手机权限/手势验证页 | 双键、触点数、IMU轴、灯/马达证据；明确单点限制 |
| P2 无实机协议闭环 | 生成码、join/reconnect、JSON输入/状态、本人接收端 | WS工具/模拟器真实控制游戏，三套鉴权隔离 |
| P3 手机完整试玩 | 独立手柄页、二维码、九宫格、体感、双键、状态 | 单人/房主/Share 都只控制本人；iOS/Android 真机可玩 |
| P4 ESP 完整试玩 | `device/esp32`固件、直接扫码、体感、显示/灯/马达 | 启动应用扫码即绑定，使用已验证的同一JSON协议 |
| P5 手感与稳定性 | 低抖动、拥塞处理、续航策略、长时运行报告 | 实机指标、连续/离散输入可靠性、网络故障与撤权通过 |
| P6 文档与发布准备 | 版本、部署说明、恢复步骤、兼容表 | 核心/插件/固件产物分别核验；标出仍未验证机型 |

先用「WS工具/模拟器 → Anka → 当前角色」验证，再做手机和ESP。
硬件P1可独立进行，不让等待机器阻塞P2/P3；摄像头与真实体感仍需真机验证。
这降低同时调试固件、协议、游戏相机和手机浏览器四层问题的难度，不减少最终交付范围。
具体排期应在 P1 触点/轴向与工具链构建结果出来后估计；本方案不虚报确定工期。

## 5. 性能与手感目标（均未实测）

| 项目 | 目标 | 测量方式 |
|---|---|---|
| 良好同区域网络，采样到游戏消费 | p50 ≤40ms，p95 ≤80ms | 跨时钟估计需报告误差；同时记录 server ingress/egress |
| 输入到真实显示变化 | 目标 p95 ≤100ms | 120/240fps 视频或设备 LED 同步标记，对齐渲染画面 |
| 紧急释放 | 最后有效输入后 ≤150ms + 一渲染帧 | 人为断网/锁屏，记录最后输入与停止移动/开火 |
| 体感静止漂移 | 完成校准后，30 秒内 yaw 漂移目标 ≤2° | 两类设备分别静止测；达不到则改滤波/默认体感模式 |
| 手势误触 | 100 次正常拖动中无功能误触 | 不同起点、甩动、回原点、边缘、轻抖动 |
| 长时稳定 | 至少 2 小时无卡键/无持续内存增长 | 手机与 ESP 各自运行，监控堆/队列/连接恢复 |
| 组合输入 | 移动 + 双主键 + 体感稳定 | 真机验证；屏幕再点功能只在多点路径承诺 |

公网距离/拥塞可能超目标，必须单独报告。WS 经服务器中继的网络下限取决于路由与 RTT。
若持续拥塞，系统应先保证停控和提示，再优化网络位置/发送策略；本期不叠加 WebRTC/局域网双链路。
不中途加入复杂预测以掩盖延迟，也不声称互联网链路达到有线手柄的确定性。

## 6. 关键验收用例

### 身份与绑定

- User / Share / Device 凭证交叉访问另外两个体系，逐项应拒绝。
- 已登录账号浏览器缺 Device 凭证，不能打开有效设备 WS；有 Device 不得加入 room WS。
- User 只绑本人 runtime；Share 只绑本人房间角色；篡改 target/player/room 字段无效。
- 同一玩家两客户端同时扫码join仅一个绑定成功；同一绑定只保留一条活动控制连接。
- 过期、重复join、旧码刷新、无效token、重连/解绑、退出账号、Share被踢立即生效。
- 设备绑定不增加大厅人数，不让手机手柄页变成玩家，不泄露账号/Share Cookie。

### 输入与手势

- 九个位置单击都只执行一次；从每格起滑都只移动，抬手立停。
- 拖出去再回原点不变成点击；快速甩动不点击；长按静止不误发技能。
- 两主键同时按住，释放其中一颗不清掉另一颗；短于渲染帧的开火不被状态合并吞掉。
- 多指、pointercancel、触点 ID 变化、窗口失焦、屏幕旋转、锁屏时不粘键。
- 鼠标/键盘接管后设备不继续转镜头；恢复必须全中立确认。
- 输入序号重复/乱序、事件去重、反馈过期、数值 NaN/越界、消息洪泛、慢接收均被处理。

### 场景与硬件

- 单人、房主、Share 三个角色来源；第一/第三人称；大厅→比赛→死亡→复活→结算。
- ESP 原理图板型、双键模式、左右槽、屏幕触点、六灯索引、IMU轴向和马达污染验证。
- iPhone Safari、iPhone 主屏、Android Chrome、Android 主屏；内嵌浏览器记录支持/降级。
- 断 Wi-Fi、服务器短重启、客户端切后台、receiver 刷新、多标签、插件卸载、切房间。
- ESP打开应用扫码直接绑定，摄像头测试明暗、反光、码距和识读超时；反向扫码暂不做。

## 7. 完成定义

功能完成 = 已授权的每条主路径有真实可玩的端到端证据，权限隔离、输入释放、
手机兼容和 ESP 限制被验证，部署/恢复说明可执行。
模拟器通过不替代传感器/马达/手机权限真机通过；构建通过不等于可玩或低延迟。
用户当前仅要求设计，本轮不执行 P1–P6，不创建功能代码、不刷机、不部署。
