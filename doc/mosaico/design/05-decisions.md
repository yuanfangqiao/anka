## 本方案建议的默认项

| 编号 | 建议 | 原因 |
|---|---|---|
| D01 | 一玩家一绑定、一绑定一活动连接 | 减少多设备仲裁，不把硬件ID当认证 |
| D02 | 生成码即授权，扫码自动绑定 | 采纳用户简化建议，二维码120秒、成功即消费 |
| D03 | JSON 协议 v1，60Hz 目标 | 先可调试和兼容，依据实测再优化 |
| D04 | 150ms 输入 watchdog | 断线/锁屏后快速停控，避免持续移动/开火 |
| D05 | 体感默认相对旋转，支持仅 ADS 生效 | 降低绝对航向漂移与握姿约束 |
| D06 | 不依赖磁力计做北向校正 | 磁吸结构等可能污染磁场 |
| D07 | 九宫格固定映射，不做自定义布局编辑器 | 减轻开发，保持滑动/点击规则清晰 |
| D08 | ESP直接扫码，反向配对后续可选 | 本期不增加activation/polling辅助流程 |
| D09 | ESP 使用 BSP + LVGL + WS，不用游戏引擎 | 手柄只渲染控制与状态，缩小固件复杂度 |
| D10 | 一条服务器 WSS 中继路线 | 暂不开发 WebRTC、蓝牙、直连发现与双链路切换 |
| D11 | WS工具/模拟器→手机→ESP | 不等真机器验证效果，再适配硬件 |
| D12 | 一张HTTPS码，同路径转换WSS | 手机开页面，ESP转换scheme，统一bindKey/token |
| D13 | input完整状态+look增量，单击用action | JSON易调试，合并时look求和并保留开火边沿 |
| D14 | 不做持久设备注册 | resumeToken存内存，短断网重连，应用重启重扫 |

## 开发前需验证而非猜测的事项

触屏实际触点数与框架暴露、设备板版本、摄像头是否安装、IMU轴向/漂移、
主板与背挂电池的实际续航、手机系统与内嵌浏览器权限、真实公网延迟。

BSP 默认 IMU 是 100Hz；设计中 200Hz 只是拟调参数。
部分 BSP 文本残留 CST9217，但下载版本 `onboard/display.c` 使用 CST9220 驱动。
不据此承诺实体屏幕多点并发，不把自检页/浏览器模拟当真机验收。
